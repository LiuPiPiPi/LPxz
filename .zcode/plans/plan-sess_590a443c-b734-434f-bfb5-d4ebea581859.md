## 目标
停止服务器构建 + 清理；改用 GitHub Actions 流水线（amd64 runner 构建 → 推送 GHCR 公开镜像 → SSH 拉取+重启容器）。同源单域名（lpxz.work 统一提供前台/后台/API；admin/api 子域名 301 跳转）。nginx 同源切换由我手动切一次，以后流水线只管镜像。

## Step 1：停止服务器构建 + 清理服务器构建产物
- 停掉服务器上正在跑的 `docker compose build`（kill 后台 ssh 任务 + 服务器进程）。
- 删除：`~/LPxz/`（rsync 的源码 + .env）、`/tmp/lpxz_build.log`、`/root/nginx-new/`（暂存配置，改由仓库托管）。
- **保留**：DB 备份 `/var/lib/lpxz/instance/lpxz.sqlite3.bak-*`、nginx 配置备份 `/root/nginx-backup-*/`、旧 `lpxz_api` 容器（保持运行，站点不中断，直到新容器接管）。

## Step 2：仓库新增同源 nginx vhost 配置（版本参考，我手动应用）
- `deploy/nginx/www.lpxz.work.conf`：lpxz.work / www.lpxz.work → 反代 `127.0.0.1:8080`（新容器），保留 acme webroot 续期。
- `deploy/nginx/admin.lpxz.work.conf`：admin.lpxz.work → 301 `https://lpxz.work/cms$request_uri`。
- `deploy/nginx/api.lpxz.work.conf`：api.lpxz.work → 301 `https://lpxz.work/api$request_uri`。
- 三份 SSL 证书路径不变（`/etc/letsencrypt/live/{lpxz.work,admin.lpxz.work,api.lpxz.work}/`）。
- 这三份就是之前暂存在 `/root/nginx-new/` 的内容，搬进仓库做版本参考；流水线**不**自动改主机 nginx。

## Step 3：仓库新增 `docker-compose.prod.yml`（镜像制，服务器运行用）
- 服务 `app`，`image: ghcr.io/liupipipi/lpxz:latest`，`container_name: lpxz`。
- `ports: 127.0.0.1:${WEB_PORT:-8080}:80`（只绑本地，由主机 nginx 反代）。
- `volumes`：`${LPXZ_DATA_DIR:-/var/lib/lpxz}/instance:/app/instance` + `/backups:/app/backups`。
- `environment`：`SQLITE_DATABASE=/app/instance/lpxz.sqlite3`、`SQLITE_BACKUP_DIR=/app/backups`（绝对路径覆盖，落持久卷）。
- `restart: unless-stopped`。**无** `build:`、**无** `env_file:`（自包含；SECRET_KEY/JWT/ADMIN 暂沿用 config.py 默认 dev-secret，与旧容器一致）。
- 开发用 `docker-compose.yml`（带 `build:`）保持不变。

## Step 4：仓库新增 `.github/workflows/deploy.yml`
- 触发：push 到 `main` + `workflow_dispatch`（手动）。
- **Job `build`（无需任何 secret，push 即跑）**：ubuntu-latest（amd64）→ checkout → `docker build -t ghcr.io/liupipipi/lpxz:latest -t ghcr.io/liupipipi/lpxz:sha-${GITHUB_SHA::7} .` → `docker login ghcr.io`（用自动 `GITHUB_TOKEN`）→ push 全部 tag。
- **Job `deploy`（`needs: build`，用 `if: ${{ vars.DEPLOY_ENABLED == 'true' }}` 门控）**：用 `appleboy/scp-action` 把 `docker-compose.prod.yml` 传到服务器 `/root/lpxz-prod/`；用 `appleboy/ssh-action`（读 secrets `SERVER_HOST`/`SERVER_USER`/`SERVER_SSH_KEY`/`SERVER_PORT`）执行：`docker pull ghcr.io/liupipipi/lpxz:latest` → `docker compose -f /root/lpxz-prod/docker-compose.prod.yml up -d`（镜像变了就重建 `lpxz` 容器）。**不动 nginx**。

## Step 5：提交 + push（触发 build job 产出镜像）
- commit 上述 4 类新文件（deploy/nginx/、docker-compose.prod.yml、.github/workflows/deploy.yml）+ push 到 main。
- push 自动触发 `build` job → 镜像进 GHCR（默认私有）。

## Step 6：用户一次性设置（GitHub UI）
- GHCR：到 `https://github.com/users/LiuPiPiPi/packages/container/lpxz/settings` 把 package 改为 **Public**（服务器免认证 pull）。
- 想启用自动部署时再加 repo secrets：`SERVER_HOST`、`SERVER_USER`(root)、`SERVER_SSH_KEY`(私钥，对应公钥已在服务器 authorized_keys)、`SERVER_PORT`(22)，并把 repo variable `DEPLOY_ENABLED=true`。**首次上线不依赖这一步**（我手动拉镜像+切 nginx）。

## Step 7：首次上线（我手动，用我的 SSH，不等 deploy job）
- GHCR 改 public 后，我在服务器：`docker pull ghcr.io/liupipipi/lpxz:latest`。
- 放置 `docker-compose.prod.yml` 到 `/root/lpxz-prod/`，`docker compose -f .../docker-compose.prod.yml up -d` 启动 `lpxz` 容器（端口 127.0.0.1:8080）。
- 用仓库 `deploy/nginx/*.conf` 覆盖 `/etc/nginx/conf.d/` 对应文件 → `nginx -t` 校验 → `nginx -s reload`。
- `docker stop lpxz_api && docker rm lpxz_api`（旧容器下线，端口 8090 释放）。
- 验证：`curl -I https://lpxz.work/`、`/cms/`、`/api/site`、`/admin/login`；`https://admin.lpxz.work` → 301 到 `/cms/`；`https://api.lpxz.work/site` → 301 到 `/api/site`；前台能加载文章、后台能登录。

## Step 8：以后自动部署（用户加好 secrets + DEPLOY_ENABLED=true 后）
- 以后每次 push 到 main：build job 重建镜像 → deploy job SSH 拉取+重启 `lpxz` 容器。nginx 不动。

## 风险/备注
- `build` job 不需要 secret，push 即出镜像；`deploy` job 需要 secrets 才跑——首次上线我手动做，不等它。
- GHCR 默认私有，需用户改 public 一次（或服务器用 PAT `docker login`，本方案选 public）。
- DB 兼容已验证：`init_db()` 有 user 表即跳过（不 drop），`ensure_log_tables`/`ensure_site_defaults` 全 `IF NOT EXISTS`+幂等插入；新 schema 与旧 DB 列级一致，迁移只是补 4 个模块开关行。
- 旧容器无 app env（用 config.py 默认 dev-secret）；新容器同样不设这些 env，行为一致。后续加固可把 SECRET_KEY/JWT/ADMIN_* 加为 GitHub secrets 并在 prod compose 用 `${{ secrets.X }}` 引用（会使登录态失效，需重新登录）。
- 回滚：恢复 `/root/nginx-backup-*/` 的 vhost + `docker start lpxz_api` + 必要时还原 DB 备份。
